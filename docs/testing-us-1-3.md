# วิธีติดตั้งและทดสอบ US-1 → US-2 → US-3

## สถานะผลตรวจจาก Codex

ตรวจวันที่ 13 พฤศจิกายน 2569 (Asia/Bangkok)

- `npm.cmd run lint`: ผ่าน
- `npm.cmd test`: ผ่าน 7 รายการ เน้นชื่องาน วันที่ ข้อมูลผิดชนิด และไม่รับทีม/ผู้สร้าง/สถานะจากฟอร์ม
- `npm.cmd run build`: ผ่าน
- ตรวจเว็บที่รันจาก build บนเครื่อง: `/login` ตอบ 200 และมีภาษาไทย; ผู้ที่ยังไม่ล็อกอินเปิด `/team`, `/tasks`, `/my` ได้ 307 ไป `/login` ทั้ง 3 เส้นทาง
- การใช้งานหลายบัญชีและกฎ RLS บน Supabase: **ยังไม่ได้ทดสอบจริง** ต้องให้เจ้าของโปรเจกต์รัน migration แล้วใช้บัญชีทดสอบตามขั้นตอนด้านล่าง
- ไม่ได้รัน SQL หรือสร้างบัญชี/ข้อมูลใน Supabase ของผู้ใช้จาก Codex

## 1. เตรียมฐานข้อมูลครั้งแรก

Migration คือไฟล์ SQL สำหรับเพิ่มโครงสร้างและกฎของฐานข้อมูล

เปิดไฟล์ใน VS Code แล้วกด Ctrl+A → Ctrl+C จากนั้น Supabase → **SQL Editor → New query** → วาง → **Run** ทำทีละไฟล์ตามลำดับ:

1. `supabase/migrations/20261113000100_us1_profiles.sql`
2. `supabase/migrations/20261113000200_us2_teams.sql`
3. `supabase/migrations/20261113000300_us3_tasks.sql`

แต่ละไฟล์ต้องขึ้น Success ก่อนเริ่มไฟล์ถัดไป รันครั้งเดียว ไม่รันซ้ำถ้าเคยสำเร็จแล้ว หากขึ้น error ให้หยุดและส่งข้อความ error โดยไม่ส่ง key หรือรหัสผ่าน ไม่มีคำสั่งลบตารางเดิมในไฟล์เหล่านี้

สำหรับ workshop: Supabase → **Authentication → Sign In / Providers → Email** → ปิด **Confirm email** → Save ตาม `docs/plan.md` เพื่อให้ AC-1.1 สมัครแล้วเข้าสู่ระบบทันที เมื่อใช้งานจริงต้องเปิดการยืนยันอีเมลกลับและตั้งค่าการส่งอีเมล

เว็บใช้สองค่าที่มีอยู่ใน `.env.local` เท่านั้น ไม่ต้องเพิ่มค่าหรือใช้ Secret key

Terminal → พิมพ์ `npm.cmd run dev` → เปิด <http://localhost:3000/login>

## 2. เตรียมบัญชี A, B และ C

ใช้บัญชีทดสอบที่คุณเป็นเจ้าของและอีเมลถูกต้อง หลีกเลี่ยงโดเมนตัวอย่างที่บริการอาจปฏิเสธ

| บัญชี | เปิดที่ไหน | สิ่งที่ทำ |
|---|---|---|
| A | หน้าต่างปกติ | สมัครชื่อ “หัวหน้า A” → สร้าง “ทีม 1” → จดรหัสเชิญ |
| B | หน้าต่างไม่ระบุตัวตน | สมัครชื่อ “สมาชิก B” → เข้าร่วมทีม 1 ด้วยรหัสของ A |
| C | อีกเบราว์เซอร์ | สมัครชื่อ “หัวหน้า C” → สร้าง “ทีม 2” → สร้างงานชื่อ “งานลับทีม 2” มอบให้ตัวเอง |

ห้ามใช้หลายแท็บในเบราว์เซอร์ session เดียวแทนหลายบัญชี เพราะจะใช้ข้อมูลล็อกอินร่วมกัน

## 3. ทดสอบ US-1 และ US-2 ก่อน

| เกณฑ์ | วิธีทำ | ผลที่ต้องเห็น |
|---|---|---|
| AC-1.1 | `/login` → สมัครสมาชิก → กรอกชื่อ อีเมล รหัสผ่านอย่างน้อย 6 ตัว | ไป `/team` และแถบบนแสดงชื่อที่กรอก |
| AC-1.2 | ออกจากระบบแล้วใช้รหัสผ่านผิด | “อีเมลหรือรหัสผ่านไม่ถูกต้อง” และอยู่ `/login` |
| AC-1.3 | ล็อกอินให้ถูก → ดูชื่อบนแถบ → กดออกจากระบบ | กลับ `/login` และเปิดหน้าทีมไม่ได้จนกว่าจะล็อกอิน |
| AC-1.4 | ล็อกอินในหน้าต่างปกติ ปิดแล้วเปิดเบราว์เซอร์ใหม่ในวันเดียวกัน | ยังเข้า `/team` ได้ หากเบราว์เซอร์ไม่ได้ตั้งลบ cookies ตอนปิด |
| AC-1.5 | หน้าต่างที่ยังไม่ล็อกอินเปิด `/team`, `/tasks`, `/my` | ทุกเส้นทางไป `/login` |
| AC-2.1 | บัญชีใหม่ไม่มีทีมเปิด `/team` | เห็น “สร้างทีม” และ “เข้าร่วมทีม” |
| AC-2.2 | A สร้างทีม 1 | เห็นชื่อทีม รหัสเชิญ 6 ตัว และ A เป็นหัวหน้า |
| AC-2.3 | B ใส่รหัสผิดก่อน แล้วใส่รหัสของ A | รหัสผิดแสดง “ไม่พบทีมจากรหัสนี้”; รหัสถูกเห็นทีม 1 และบทบาทสมาชิก |
| AC-2.4 | A/B ที่มีทีมแล้วเปิด `/team` แล้วใช้สคริปต์ข้อ 5 ส่งคำขอสร้าง/เข้าร่วมทีมซ้ำ | ไม่เห็นฟอร์มสร้าง/เข้าร่วม; คำขอตรงถูกปฏิเสธด้วย ALREADY_IN_TEAM และไม่สร้างทีมเพิ่ม |
| AC-2.5 | บัญชียังไม่มีทีมกดสร้างโดยไม่กรอกชื่อ | “กรุณากรอกชื่อทีม” และยังไม่มีทีม |
| AC-2.6 | C เปิด `/team` | เห็นแค่ทีม 2 ไม่เห็นชื่อ รหัสเชิญ หรือสมาชิกทีม 1; ใช้คำขอ API ตามหัวข้อเสริมเพื่อตรวจชั้นฐานข้อมูล |

## 4. ทดสอบ AC-3.1 ถึง AC-3.7 บนหน้าจอ

| เกณฑ์ | วิธีทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| **AC-3.1** | A เปิด `/tasks` กรอกชื่องาน “จัดทำรายงาน” รายละเอียด วันกำหนดส่ง แล้วเลือก B → สร้างงาน จากนั้นสร้างอีกงานมอบให้ A และปล่อยรายละเอียด/วันกำหนดส่งว่าง | ตัวเลือกมี A และ B เท่านั้น ไม่มี C งานใหม่ขึ้นคอลัมน์ “ยังไม่เริ่ม” ทันที พร้อมข้อความสำเร็จ งานที่ไม่เลือกวันแสดง “ไม่มีกำหนดส่ง” |
| **AC-3.2** | เปิด `/tasks` ทั้ง A และ B แล้วโหลดหน้าใหม่ | ทั้งสองเห็นงานทีม 1 เหมือนกัน มี 3 คอลัมน์ “ยังไม่เริ่ม / กำลังทำ / เสร็จแล้ว” การ์ดแสดงชื่องาน ชื่อผู้รับ และวันที่ไทย เช่น `13 พ.ย. 2569` |
| **AC-3.3** | B เปิด `/tasks` | ไม่เห็นฟอร์ม/ปุ่มสร้างงาน จากนั้นใช้สคริปต์ในข้อ 5 ตรวจคำขอตรงฐานข้อมูลด้วยบัญชี B ต้องถูกปฏิเสธ |
| **AC-3.4** | A เปิดรายชื่อผู้รับงาน | ไม่มีชื่อ C จากนั้นใช้สคริปต์ข้อ 5 ส่ง assignee_id ของ C ตรงไป Data API ต้องถูกปฏิเสธ และไม่มีงานถูกเพิ่ม |
| **AC-3.5** | A เว้นชื่องานว่าง แล้วกดสร้างงาน ทำซ้ำด้วยการพิมพ์เฉพาะช่องว่าง | แสดง “กรุณากรอกชื่องาน” ใต้ช่อง ไม่สร้างงาน สคริปต์ข้อ 5 ตรวจว่าฐานข้อมูลปฏิเสธชื่อว่างด้วย |
| **AC-3.6** | ก่อนสร้างงานแรกในทีม เปิด `/tasks`; ใช้อีกบัญชีใหม่ที่ยังไม่มีทีมเปิด `/tasks` | ทีมว่างแสดง “ยังไม่มีงานในทีม”; บัญชีไม่มีทีมถูกพาไป `/team` |
| **AC-3.7** | A/B เปิด `/tasks` และ C เปิด `/tasks` โดย C มี “งานลับทีม 2” อยู่จริง | A/B ไม่เห็นงานลับทีม 2 และ C ไม่เห็นงานของทีม 1 สคริปต์ข้อ 5 ต้องคืนรายการว่างเมื่อ A ขออ่าน team_id ของทีม 2 |

ทดสอบ AC-3.2 กับข้อมูลครบทุกคอลัมน์: ใน **Supabase → Table Editor → tasks** เปลี่ยน `status` ของงานทดสอบสองชิ้นเป็น `doing` และ `done` แล้วโหลดกระดานใหม่ ต้องย้ายไปคอลัมน์ถูกต้อง ขั้นตอนนี้ทำด้วยสิทธิ์เจ้าของฐานข้อมูลเพื่อเตรียมข้อมูลเท่านั้น ยังไม่มีหน้าปรับสถานะของ US-4

ทดสอบหน้าจอแคบ: กด F12 → สลับโหมดมือถือ → เลือกความกว้าง 375px คอลัมน์ต้องเรียงลงมา อ่านและกดฟอร์มได้โดยไม่ต้องเลื่อนแนวนอน ทดลองกด Tab เพื่อเข้าถึงช่องและปุ่ม และกด Enter เพื่อส่งฟอร์ม

## 5. ตรวจ AC-3.3, AC-3.4 และ AC-3.7 ด้วย Data API จริง

Data API คือช่องทางเรียกฐานข้อมูลจากภายนอกเว็บ ส่วน RLS คือกฎจำกัดว่าแต่ละบัญชีอ่านหรือเขียนแถวใดได้ การทดสอบนี้ข้ามฟอร์มของเว็บ จึงตรวจว่าฐานข้อมูลป้องกันเองจริง

ต้องเตรียม A/B/C ตามข้อ 2 และให้ C สร้าง “งานลับทีม 2” ก่อน เพื่อไม่ให้ผล “ไม่เห็นงานทีมอื่น” ผ่านเพียงเพราะทีมอื่นไม่มีงาน

เปิด Terminal อีกช่องในโฟลเดอร์โปรเจกต์แล้วพิมพ์:

```powershell
node --env-file=.env.local scripts/check-us3.mjs
```

1. อ่านข้อความ โปรแกรมนี้จะสร้างงานทดสอบ **2 งาน** ในทีม 1 และเก็บไว้บนกระดาน ไม่มีการลบข้อมูล
2. พิมพ์ `TEST` เพื่อเริ่ม
3. กรอกอีเมลและรหัสผ่าน A → B → C ตามคำถาม รหัสผ่านไม่แสดงขณะพิมพ์และไม่ถูกบันทึกลงไฟล์ ไม่ต้องส่งค่าในแชท
4. โปรแกรมใช้ publishable key กับ token ที่ได้รับหลังล็อกอินบัญชีนั้นจริง ไม่ใช้ Secret key และไม่ใช้ SQL Editor
5. ต้องขึ้น “ผ่าน” ทุกข้อ รวมถึงสมาชิกสร้างไม่ได้ ผู้รับคนนอกทีมถูกปฏิเสธ ปลอมผู้สร้าง/ทีม/สถานะไม่ได้ และอ่านงานข้ามทีมไม่ได้
6. กลับหน้า `/tasks` ของ A/B และโหลดใหม่ ต้องเห็นงานทดสอบทั้งสองงานในคอลัมน์ยังไม่เริ่ม

ถ้าขึ้น “ไม่ผ่าน” หรือ “ติดต่อระบบไม่ได้” อย่าสรุปว่าทดสอบผ่าน ตรวจการเตรียมบัญชีและ migration แล้วส่งเฉพาะข้อความผลทดสอบ ไม่ส่ง key/token/รหัสผ่าน โปรแกรมออกจากระบบเฉพาะ session ของการทดสอบเมื่อจบ

สคริปต์ไม่แทนการตรวจข้อความ วันที่ การซ่อนฟอร์ม และการเปลี่ยนเส้นทางบนเว็บในข้อ 4

### ตรวจตารางทีมและโปรไฟล์เพิ่ม (AC-2.6)

สคริปต์ข้อ 5 ตรวจ SELECT `teams`, `team_members`, `profiles` ภายใต้ token ของ C และกรองรหัสของ A/B ให้ด้วย ต้องคืนรายการว่าง ห้ามใช้ผลใน Table Editor แทน เพราะหน้าจอนั้นใช้สิทธิ์เจ้าของฐานข้อมูลที่เห็นทุกทีมได้
