# วิธีติดตั้งและทดสอบ US-4: อัปเดตสถานะงาน

## สิ่งที่เพิ่ม

- AC-4.1 ผู้รับงานเลือก “ยังไม่เริ่ม / กำลังทำ / เสร็จแล้ว” แล้วกด “บันทึกสถานะ” งานย้ายคอลัมน์ทันทีเมื่อสำเร็จ
- AC-4.2 หัวหน้าเปลี่ยนสถานะทุกงานในทีมได้
- AC-4.3 สมาชิกคนอื่นและคนนอกทีมไม่มีสิทธิ์แก้ แม้ส่งคำขอตรงฐานข้อมูล
- AC-4.4 ฐานข้อมูลจำกัดผู้รับงานให้เปลี่ยนได้เฉพาะ status ตรวจทุกคอลัมน์ก่อนบันทึกและตั้ง updated_at เอง
- AC-4.5 งานที่กำหนดส่งก่อนวันนี้ตามเวลาประเทศไทยและยังไม่เสร็จมีป้าย “เลยกำหนด”

## 1. นำกฎฐานข้อมูลใหม่ไปใช้

ไฟล์ US-1, US-2 และ US-3 ต้องรันสำเร็จแล้ว และมีบัญชี/ทีมสำหรับทดสอบ ไม่ต้องรันสามไฟล์เดิมซ้ำ

1. เปิด `supabase/migrations/20261113000400_us4_task_status.sql` ใน VS Code
2. กด Ctrl+A → Ctrl+C
3. Supabase → **SQL Editor → New query** → วาง → **Run**
4. ต้องเห็น Success ก่อนทดสอบหน้าเว็บ หากมี error ให้หยุดและส่งเฉพาะข้อความ error ไม่ส่ง key หรือรหัสผ่าน
5. เปิด Terminal รัน `npm.cmd run dev` แล้วเข้า <http://localhost:3000/tasks> ถ้าเปิดเว็บไว้แล้วให้โหลดหน้าใหม่

ไฟล์ใหม่นี้เพิ่มสิทธิ์ UPDATE ที่มี RLS (กฎจำกัดการเข้าถึงแต่ละแถว) และ trigger (กฎที่ฐานข้อมูลตรวจทุกครั้งก่อนบันทึก) โดยไม่ลบงานเดิม ไม่ต้องเพิ่มค่าการเชื่อมต่อใน `.env.local`

## 2. เตรียมบัญชีและงาน

ใช้บัญชีเดิมจาก US-3 ได้:

| บัญชี | บทบาท | งานที่ต้องเตรียม |
|---|---|---|
| A | หัวหน้าทีม 1 | สร้าง “งานของ B” มอบให้ B และกำหนดส่งเมื่อวาน; สร้าง “งานของ A” มอบให้ตัวเอง |
| B | สมาชิกทีม 1 | ล็อกอินในหน้าต่างไม่ระบุตัวตน |
| C | หัวหน้าทีม 2 | ล็อกอินในอีกเบราว์เซอร์ แล้วสร้างงานของทีม 2 |

ทดสอบพร้อมกันให้ใช้คนละ session เช่น หน้าต่างปกติ / หน้าต่างไม่ระบุตัวตน / อีกเบราว์เซอร์ ไม่ใช้หลายแท็บของหน้าต่างเดียวแทนหลายบัญชี

## 3. ทดสอบ AC-4.1 ถึง AC-4.5 บนเว็บ

| เกณฑ์ | การกระทำ | ผลที่ต้องได้ |
|---|---|---|
| **AC-4.1** | B เปิด `/tasks` ที่ “งานของ B” เลือก “กำลังทำ” แล้วกด “บันทึกสถานะ” จากนั้นเลือก “เสร็จแล้ว” แล้วลองเลือกกลับเป็น “ยังไม่เริ่ม” | มีข้อความ “บันทึกสถานะงานสำเร็จ” การ์ดย้ายไปคอลัมน์ใหม่พร้อมจำนวนงานที่อัปเดตทันที ไม่ต้องกดโหลดหน้าเอง |
| **AC-4.2** | A เปลี่ยนสถานะทั้ง “งานของ A” และ “งานของ B” | เห็นตัวเลือกและบันทึกได้ทุกงานในทีม 1 |
| **AC-4.3** | B ดู “งานของ A”; C ดูกระดานทีม 2 | B ไม่เห็นช่อง/ปุ่มเปลี่ยนสถานะบนงาน A; C ไม่เห็นงานทีม 1 ใช้สคริปต์ข้อ 4 ส่งคำขอตรงเพื่อยืนยันว่าแก้ไม่ได้จริง |
| **AC-4.4** | ใช้สคริปต์ข้อ 4 ภายใต้บัญชี B ลองแก้ชื่องาน รายละเอียด กำหนดส่ง และผู้รับงานของ “งานของ B” รวมถึงส่งสถานะพร้อมชื่องาน | ฐานข้อมูลปฏิเสธทั้งคำขอ ข้อมูลเดิมทุกช่องรวมถึง updated_at ต้องไม่เปลี่ยน ในเว็บมีเพียงช่องแก้สถานะ |
| **AC-4.5** | งานของ B กำหนดส่งเมื่อวาน ให้ B เปลี่ยนเป็น “กำลังทำ” แล้วเป็น “เสร็จแล้ว” แล้วกลับเป็น “ยังไม่เริ่ม” | เมื่อกำลังทำ/ยังไม่เริ่มมีป้ายสีแดง “เลยกำหนด”; เมื่อเสร็จแล้วป้ายหายทันที เปิดกลับมาทำต่อแล้วป้ายกลับมา |

ตรวจ AC-4.5 เพิ่ม: ให้ A สร้างงานกำหนดส่งวันนี้ งานกำหนดส่งพรุ่งนี้ และงานไม่มีกำหนดส่ง ทั้งสามงานต้องไม่มีป้ายเลยกำหนด วันนี้อ้างอิง Asia/Bangkok ไม่ใช่ timezone ของคอมพิวเตอร์หรือเซิร์ฟเวอร์ หากเปิดเว็บข้ามวันให้โหลดหน้าใหม่

ตรวจกรณีบันทึกชนกัน: เปิดงานเดียวกันสองหน้าต่าง A/B ให้ A เปลี่ยนสถานะก่อน จากนั้น B ซึ่งยังเห็นสถานะเดิมกดบันทึก ต้องแจ้งให้ตรวจสถานะล่าสุดและไม่ทับสถานะที่ A เพิ่งแก้

ตรวจข้อผิดพลาด: ถ้ายังไม่รัน migration US-4 การบันทึกต้องไม่แสดงว่าสำเร็จและต้องไม่ย้ายงาน หลังแก้การตั้งค่าแล้วจึงลองบันทึกอีกครั้ง

ตรวจมือถือ: กด F12 → โหมดมือถือ → ความกว้าง 375px ต้องอ่านชื่อ/ป้ายและเลือกสถานะได้โดยไม่เลื่อนแนวนอน ลองกด Tab เพื่อไปที่ select และปุ่ม แล้วกด Enter เพื่อบันทึก

## 4. ตรวจสิทธิ์จริงผ่าน Data API

Data API คือช่องทางเรียกฐานข้อมูลโดยข้ามหน้าจอแอป จึงพิสูจน์ได้ว่ากฎที่ฐานข้อมูลทำงานเอง ห้ามใช้ Table Editor หรือ SQL Editor แทนผลทดสอบนี้ เพราะเจ้าของฐานข้อมูลมีสิทธิ์ต่างจากผู้ใช้เว็บ

เปิด Terminal อีกช่องในโฟลเดอร์โปรเจกต์ แล้วรันเอง:

```powershell
node --env-file=.env.local scripts/check-us4.mjs
```

1. อ่านข้อความผลกระทบ: โปรแกรมสร้างงานทดสอบใหม่ **3 งานต่อครั้ง** (ทีม 1 สองงาน ทีม 2 หนึ่งงาน) แล้วทดสอบเฉพาะงานเหล่านั้น ไม่มีการลบข้อมูลเดิม
2. พิมพ์ `TEST` เพื่อเริ่ม
3. กรอกอีเมลและรหัสผ่าน A → B → C ตามคำถาม รหัสผ่านไม่แสดงขณะพิมพ์ ไม่ถูกเขียนลงไฟล์ และไม่ต้องส่งค่าในแชท
4. โปรแกรมใช้ Publishable key กับ token ของผู้ใช้จริง ไม่ใช้ Secret key ไม่รัน SQL และออกจากระบบเฉพาะ session ของการทดสอบเมื่อจบ
5. ต้องขึ้น “ผ่าน” ทุกข้อ ถ้ามี “ไม่ผ่าน” ให้หยุดและส่งเฉพาะข้อความผลทดสอบ

โปรแกรมตรวจ:

- B เปลี่ยนงานตัวเองได้ครบทั้งสามสถานะ และ updated_at เปลี่ยนโดยฐานข้อมูล
- A เปลี่ยนสถานะงานตัวเองและงานที่มอบให้ B ได้
- B แก้งานของ A ไม่ได้ และอ่านกลับด้วย A ยืนยันว่าไม่เปลี่ยนจริง
- B แก้ title, detail, due_date, assignee_id ไม่ได้ รวมถึง id, team_id, created_by, created_at, updated_at
- การส่ง status พร้อมแอบแก้ title ต้องถูกปฏิเสธทั้งคำขอ ไม่มีการบันทึกบางส่วน
- สถานะนอก todo/doing/done ถูกปฏิเสธโดย CHECK ของฐานข้อมูล
- C แก้งานทีม 1 ไม่ได้ และ A แก้งานทีม 2 ไม่ได้
- หัวหน้าก็ย้ายงานข้ามทีมหรือมอบงานให้คนนอกทีมไม่ได้

เมื่อจบ งานทดสอบของ B จะอยู่ “กำลังทำ” และกำหนดส่งเมื่อวาน งานของ A อยู่ “เสร็จแล้ว” งานของ C อยู่ “ยังไม่เริ่ม” ในทีม 2 ให้โหลดกระดานแล้วทดสอบป้าย AC-4.5 ตามข้อ 3 ต่อ

สคริปต์นี้ตรวจฐานข้อมูล ส่วนการย้ายคอลัมน์ทันที การซ่อนฟอร์ม ข้อความ และป้ายสี ต้องตรวจบนเว็บด้วย
